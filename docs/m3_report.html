1How we addressed the Milestone 2 feedback

"Focus on when and why structured execution helps." We no longer ask whether C4 beats C2 on average. Each item carries features that may decide when structure matters (distance to the threshold, one or two bounds, a distractor number that would flip the answer, report revisions, domain), and we vary model size. To explain why, we split each error by stage (rule, value or comparison) and by kind (reasoning or only format).

"Your eval data is artificial." We dropped the edited contracts. Every item is now a real settled Kalshi market, scored against Kalshi's real outcome, with the real evidence that its rules name. The gold comes from Kalshi's own data, so no hand labels are needed.

2System implemented so far

Data113,152 settled markets in 21 series, closed 2026-09-11 to 2026-11-16 (public Kalshi API). Kalshi's threshold field applied to the settled value reproduces the outcome on 113,094 of 113,095 markets with a numeric value. The one exception is a real edge case: a Nasdaq-100 market whose threshold field (26,990) differs from its rules text ("above 26,989.99"); the text decided it.
EvidenceWeather: the NWS daily climate report for the station the rules name. It matches Kalshi's value on 366 of 367 station-days. It also lists the record, normal, departure, last-year value and the other daily extreme; on 56% of weather items one of these would flip the answer. A variant gives the preliminary and the final report together. Finance and economics: one line with the official value.
Study set666 items in 100 events (weather 384, finance 144, economics 138), split by event: dev 162 items (25 events), test 504 (75 events). Prompts change on dev only; test is untouched.
MethodsB1 no evidence · C1 direct answer · C2 chain of thought · C3 LLM writes a JSON spec, extracts the value, applies the spec in prose · C4 LLM writes the spec and extracts the value, Python applies the spec · O1, O2 C4 given the gold spec or the gold value. Built but not run yet: C2-SC (5-sample vote), B2 (no rules), O3.
ModelsGroq API, temperature 0: ALLaM 2 7B, Qwen 3.8 27B (reasoning off), gpt-oss 20B (reasoning low). Llama 3.1 from our Milestone 2 plan is no longer served there, so ALLaM is our small model.
ScoringStrict: the answer must follow the output format. Tolerant: the saved output re-read with format repairs only (a "verdict is NO" sentence, bounds in the wrong JSON field, a value written before the JSON was cut off), with no new LLM calls. ABSTAIN and invalid count as wrong. Intervals: paired bootstrap over events.
EngineeringAll calls cached; runs resume; a self-test checks gold rules, evaluator and parsers; a Streamlit demo runs C2 and C4 side by side.

3Baseline results

B1 (no evidence) on Qwen 27B has a balanced accuracy of 0.50 (n = 96), which is chance: the contract text does not give the outcome away, and the model shows no sign of knowing these 2026 outcomes. C1 (direct answer) is the baseline to beat: 100.0% on Qwen 27B (162 of 162), 77.2% on ALLaM 7B, and 96.4% on gpt-oss 20B with both reports.

Our answer so far. When: structure helps when the direct answer fails. On real markets this happens with a small model, with long evidence full of distractors, near the threshold and on two-bound rules. With a 27B model, the direct answer is already right on every dev item.

Why: the direct answer fails at the comparison (a YES bias and wrong calls at inclusive bounds), and code makes the comparison exact. Why not always: each extra JSON step is a new place to break the format, so strict C4 loses until the pipeline handles the format itself (plan item 2).

5Experiments and comparisons completed

  • E1 baselines (B1, C1); E2 main methods (C1, C4 on all dev items for ALLaM 7B and Qwen 27B, Qwen C4 and C2 in part); E3 scale (7B, 20B, 27B); the revision variant (both reports, gpt-oss 20B); pilot spec format v1 against v2.

6What worked

  • Structure helps the small model: C4 beats C1 on ALLaM 7B by +19.1 points (95% CI +9.5 to +30.4), n = 162. The gain is larger in every harder cell (Figure 1B).
  • Real data with exact gold: no labels and no generated items. Hard cases are common: 51 of 162 dev items are within 1 step of the threshold, 43 have a flipping distractor.
  • Tolerant scoring separates "reasoned wrong" from "broke the format", at no cost.

7What failed

  • Strict C4 on the small model: 56.8% against 72.8% for strict C1, −16.0 points (95% CI −29.9 to −3.3). C4 has 2 JSON outputs where C1 has 1.
  • No room to help a 27B model: Qwen 27B answers all 162 dev items directly.
  • Two reports break ALLaM 7B: with about 3,300 input tokens (its context is 4,096) it loops or prints blank lines: no valid answer on 7 of 7, so we stopped that run.
  • Compute: the free Groq tier's daily token limit per model left C2, the oracles and test incomplete.

8Failure analysis and likely causes

  • ALLaM 7B, direct answer. 37 of 162 are wrong, and 34 of these say YES on a NO market: it answers YES 48.8% of the time against a true rate of 29.6%. Of the 30 weather errors, 18 give only a verdict, 7 cite a wrong value, and 5 cite the right value but compare it wrongly at a bound (70 judged outside "69° to 70°"). Likely cause: the comparison step. C4 fixes 34 of the 37, because Python does the comparison.
  • ALLaM 7B, strict C4. All 70 errors are on weather. 34: the extractor wrote the right value, then copied the report line "word for word" as asked; the report's fixed-width columns are long runs of spaces, so it hit the token cap before closing the JSON. 30: for "between" rules it put [low, high] in the "threshold" field. Only 6 are real value errors, each a distractor (last year 2, normal 2, other 2).
  • gpt-oss 20B, both reports. C1 abstains on 3 of 84 items, 2 of them on the one dev day where the reports disagree (NYC low: preliminary 58, final 54); it does not fall back to the later report. C4 takes a wrong value 3 times, each time the record high, which sits next to the observed value in the same row.
  • Revisions are rare in real markets. The two reports differ on 6 of 84 dev weather items and change the outcome on 2 (test: 12 and 2 of 300), far fewer than in the edited set we had planned.
